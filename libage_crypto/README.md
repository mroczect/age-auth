# libage_crypto

Age encryption/decryption backend for the age-auth authenticator.  
This crate provides an implementation of the `CryptoBackend` trait using the [rage](https://github.com/str4d/rage) library.

## Features

- **Full `CryptoBackend` implementation** – encrypt and decrypt secrets using X25519 age identities.
- **Multiple recipients** – encrypt once for several public keys with `encrypt_multiple`.
- **Key generation** – generate new age keypairs that are immediately ready to use with the handler types.
- **Zeroize** – plaintext and ciphertext are extracted with `std::mem::take` and wrapped in `Zeroizing`, ensuring memory is cleared after use.
- **No panics** – all fallible operations return `Result<_, AuthError>`; `unwrap`/`expect` are never used in production code.
- **Minimal dependencies** – only depends on `libage_auth_handler` and `librage`.

## Quick Start

```rust
use libage_crypto::{AgeCrypto, generate_keypair};
use libage_auth_handler::traits::CryptoBackend;
use libage_auth_handler::types::Secret;

// Generate a fresh keypair
let (recipient, identity) = generate_keypair()?;

// Create a secret
let secret = Secret::new(b"Hello, age!".to_vec());

// Encrypt
let backend = AgeCrypto;
let encrypted = backend.encrypt(&recipient, &secret)?;

// Decrypt
let decrypted = backend.decrypt(&identity, &encrypted)?;
assert_eq!(decrypted.as_bytes(), secret.as_bytes());
```

## API Reference

### `AgeCrypto`

Zero‑sized struct that implements `CryptoBackend`.

```rust
pub struct AgeCrypto;
```

`AgeCrypto` delegates to the `librage` crate for the underlying cryptographic operations.

#### `CryptoBackend` implementation

```rust
impl CryptoBackend for AgeCrypto {
    fn encrypt(&self, recipient: &Recipient, plaintext: &Secret)
        -> Result<EncryptedPayload>;
    fn decrypt(&self, identity: &Identity, ciphertext: &EncryptedPayload)
        -> Result<Secret>;
}
```

- **`encrypt`** – encrypts `plaintext` for the given `recipient` (age public key). Returns `EncryptedPayload`.
- **`decrypt`** – decrypts `ciphertext` using the provided `identity` (age secret key). Returns the original `Secret`.

Both methods:

- Accept already‑validated `Recipient` / `Identity` types.
- Never panic; all errors are mapped to `AuthError`.
- Use `std::mem::take` to move data out of the `Zeroizing` wrappers from `librage`, preserving zeroize semantics.

### `encrypt_multiple`

```rust
pub fn encrypt_multiple(
    recipients: &[Recipient],
    secret: &Secret,
) -> Result<EncryptedPayload>
```

Encrypts `secret` so that **any** of the provided private keys (identities) can decrypt it.

- `recipients` – slice of `Recipient` values (age public keys).
- Returns an `EncryptedPayload` that can be decrypted with any matching identity.

Example:

```rust
let (r1, id1) = generate_keypair()?;
let (r2, _)   = generate_keypair()?;
let secret = Secret::new(b"multi‑recipient".to_vec());

let encrypted = encrypt_multiple(&[r1, r2], &secret)?;
let decrypted = AgeCrypto.decrypt(&id1, &encrypted)?;
assert_eq!(decrypted.as_bytes(), secret.as_bytes());
```

### `generate_keypair`

```rust
pub fn generate_keypair() -> Result<(Recipient, Identity)>
```

Generates a new X25519 age keypair.

- Returns a tuple `(recipient, identity)` where:
  - `recipient` is a valid `Recipient` (age public key starting with `"age1"`).
  - `identity` is a valid `Identity` (age secret key starting with `"AGE-SECRET-KEY-"`).

The underlying secret is generated by `librage::generate_keypair` and is zeroized after being converted into the `Identity` type.

## Error Handling

All public functions return `libage_auth_handler::errors::Result<T>` (alias for `std::result::Result<T, AuthError>`).

The module `error` (private) contains a helper `from_librage_error_body` that maps `librage::ErrorBody` into `AuthError`:

| librage error code                                       | AuthError variant         |
| -------------------------------------------------------- | ------------------------- |
| `INVALID_PUBLIC_KEY`, `INVALID_SSH_KEY`, `INVALID_INPUT` | `AuthError::InvalidInput` |
| `INVALID_SECRET_KEY`                                     | `AuthError::Crypto`       |
| `IO_ERROR`                                               | `AuthError::Io`           |
| Any other code                                           | `AuthError::Crypto`       |

This ensures consistent error reporting across the workspace.

## Security

- **Zeroization**: `librage` returns ciphertext and plaintext wrapped in `Zeroizing`. `AgeCrypto` moves the data out with `std::mem::take`, leaving the original `Zeroizing` container empty (which is then dropped and its remaining capacity zeroized). The extracted data is immediately placed into `Secret` or `EncryptedPayload`, both of which are zeroized on drop.
- **No panics**: all error paths use `ok_or_else` and never call `unwrap`/`expect`.
- **Input validation**: `Recipient` and `Identity` are already validated when constructed (by `libage_auth_handler`), so `AgeCrypto` only receives well‑formed values.
